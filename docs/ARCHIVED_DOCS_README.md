- **Debugging historical issues**: Check SNEAKY_BUGS_ROOT_CAUSE_ANALYSIS.md first, then archived analysis docs
- **Understanding how something was fixed**: See CRITICAL_FIXES_APPLIED_SESSION4.md in archive
- **Learning about old approaches**: Reference archived DESIGN_REVIEW or BEFORE_AFTER docs
- **Session-specific context**: Look in SESSION* files in archive

## 📝 Going Forward

When creating new documentation:
- **Edit existing core docs** rather than creating new ones for the same system
- **Use status headers** (✅ COMPLETE, ⚠️ IN PROGRESS, 🔄 DEPRECATED) for clarity
- **Link to code** with specific file and line numbers when referencing implementation
- **Archive session-specific work** to `/archived-docs/` after sessions complete
