## 🔄 Going Forward: Documentation Strategy

### When to Create New Docs
Only create new documentation for:
- ✅ **New systems** (not yet documented)
- ✅ **Major architecture changes** that affect multiple components
- ❌ **Session-specific work** → Update existing docs instead
- ❌ **Iteration variants** → Update existing docs instead
- ❌ **Redundant versions** → Archive and consolidate

### When to Archive Docs
Archive docs when:
1. They become outdated (covered by newer docs)
2. They're session-specific logs (SESSION*, FIXES_SYNC, etc.)
3. They're phase-specific (PHASE1, PHASE2 variants)
4. They're iteration snapshots (ELITE_*, REDESIGN, REVIEW variants)
5. They duplicate information from active docs

### How to Update Docs
- **Edit existing docs** to add new information
- **Use status headers**: ✅ COMPLETE, ⚠️ IN PROGRESS, 🔄 DEPRECATED, ❌ BROKEN
- **Add context headers** to clarify: Purpose, Scope, Status, Last Updated, Location
- **Link to code** with specific file paths and line numbers
- **Cross-reference** related docs at the top

### Archive Workflow
After completing work on a system:
1. Update the core reference doc with all changes
2. Ensure VERIFICATION_CHECKLIST has test procedures
3. Update SNEAKY_BUGS if new issues discovered
4. Move session-specific docs to `/archived-docs/`
5. Update ARCHIVED_DOCS_README.md with new archive links
